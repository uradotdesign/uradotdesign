# Deployment audit fixes

Scope: D01–D13 from [the follow-up audit](audit-deployment-followup-2026-09-10.md). All proposed product features were declined and are excluded.

## Changes

- **D01:** the renewed certificate includes apex and www; HTTP and HTTPS www preserve path/query while redirecting to the apex. The version-controlled Nginx configuration is `ops/nginx/ura.design.conf`.
- **D02:** only fingerprinted `/_astro/` files receive immutable caching. Generated OG headers are respected, and their metadata URLs carry a publication generation to escape previously cached URLs. Directus assets use a five-minute browser TTL with their original access/privacy policy.
- **D03:** daily local, encrypted backups at 03:35 UTC (up to ten minutes of jitter), retaining 14 successful archives. This is explicitly local-only at the user's request. Each backup restores the database in a network-isolated temporary Postgres container, verifies upload references, and checks archive decryption before marking success. Encryption identity: root-only `/etc/ura/backup.agekey`; archives and age markers: `/var/backups/ura`. Legacy checkpoints remain untouched. These backups share the VPS's failure domain.
- **D04:** random shared generations and an atomic Lua write fence prevent pre-publication reads from repopulating a new generation. In-flight coalescing includes the generation. Versioned cache keys allow old/new application containers to overlap safely; Redis failure still falls back to an upstream read. Failed purges remain visible to Directus as 503.
- **D05:** testimonial tabs control real panels, hide inactive content, support arrows/Home/End with focus, and expose 32px targets while retaining the small visual dots. Listeners belong to the current DOM, avoiding stale document handlers after navigation.
- **D06:** CI builds and streams the release images; production does not rebuild them. A restricted SSH identity accepts only class-manifest export, deployment of an exact main-branch SHA, and health inspection. A candidate on port 4322/4323 must pass content/OG/feed checks before Nginx switches. Failures keep or restore the previous upstream. CMS recreation/extension installation only occurs when its tracked inputs change. Fingerprinted assets survive releases for up to a year. Actions and base images are digest/commit pinned.
- **D07:** per-container logs rotate at 10MB × 3. Astro has a 512MiB/1CPU budget; Postgres has 512MiB, 40 connections and 2MB work_mem; Directus's pool is capped at 10, with two concurrent image transforms. Redis has a 384MiB container limit and a 256MB no-eviction budget, preserving enforcement state until its expiry. This is a measured starting budget, not a claimed load-capacity result.
- **D08:** an external GitHub Actions check runs every 15 minutes and fails for public HTTP/TLS errors, overdue backup/restore checks, unhealthy containers, inactive required flows, terminal failed non-condition flow operations, low disk space or certificates within 21 days of expiry. GitHub's Actions notification preferences determine delivery; no new email integration or dashboard was added.
- **D09:** the application now has an actual shared Redis HTML cache with a 15-second lifetime, a 512KiB response ceiling and release-specific keys. Publication advances the same generation used by the HTML cache. Preview/query variants, cookies, authorization, ranges, non-GET requests, errors, non-HTML responses, explicit response cache policies and Set-Cookie responses cannot populate it. Responses are not coalesced before their privacy is known. Browsers revalidate.
- **D10:** offscreen video pauses, hidden video does not preload, saving-data/reduced-motion preferences prevent autoplay, and source MIME follows media metadata. Video remuxing retains all 610 frames, 3240×2160 resolution and the exact encoded video packet hash. It saves only 107 bytes (5,672,267 → 5,672,160), not a meaningful codec reduction. The light WebP remains its original 84,656 bytes: lossless recoding grew to 565,904 bytes; a 79,366-byte lossy candidate was rejected to preserve quality. No downscaling, frame removal or lossy replacement was deployed.
- **D11:** sitemap queries use bounded keyset pagination with published filtering; blog counts use Directus aggregation instead of downloading up to 5,000 IDs.
- **D12:** a failed cold-cache CMS read returns non-cacheable RSS 503 with Retry-After; a genuinely empty collection still returns valid RSS 200.
- **D13:** per-IP Directus limiting allows 100 requests/second; global limiting allows 500/second. Counts use Redis and correct proxy attribution. Monitor and tune based on real request rates rather than tightening these budgets blindly.

## Operation and recovery

The root-owned entry points are installed from `ops/`: `/usr/local/sbin/ura-deploy`, `ura-ci-operation`, `ura-backup`, `ura-health`, and `/usr/local/bin/ura-ssh-command`. The `uradeploy` account has neither unrestricted SSH commands nor membership in the Docker group. Its narrowly scoped sudo entry is `/etc/sudoers.d/ura-deploy`. Root's existing operator access remains available.

`production` environment secrets are `SSH_HOST`, `SSH_USER`, `SSH_PRIVATE_KEY`, and `SSH_KNOWN_HOSTS`. The host key is pinned, not accepted from a fresh scan during deployment. Private runtime variables remain on the VPS; CI receives only the CMS class-token manifest. Never print the runtime environment or backup contents.

Current deployment state lives in `/var/lib/ura-deploy`: `active-port`, `active-revision`, `backend-hash` and `upstream.previous`. Nginx's active upstream is `/etc/nginx/conf.d/ura-upstream.conf`. Previous application containers/images are retained so rollback does not require rebuilding. A failed candidate never receives traffic; a failure after switching restores the saved Nginx upstream. Database major-version rollback still requires the documented restore procedure, rather than automatically running an older CMS against a migrated database.

For a manual rollback, inspect the retained container and image, start it if necessary, point the upstream at its loopback port, run `nginx -t`, reload, and verify both languages. Update the active-port/revision markers to match. The next deployment replaces the inactive 4322/4323 slot. Stop the initial legacy 4321 instance after the first successful migration and grace period.

Install/update host entry points deliberately as root from the reviewed revision. Use `install` with executable modes, install the backup service/timer, run `systemctl daemon-reload`, and enable `ura-backup.timer`. Nginx changes require `nginx -t` before reload. Do not alter unrelated VPS services or volumes.

Run `systemctl start ura-backup.service` for a fresh checkpoint. Run `/usr/local/sbin/ura-backup --verify` to decrypt and restore the latest archive again. `systemctl status ura-backup.timer` shows the schedule. Failures leave the last-success marker unchanged so external checks alert when overdue; failed partial work is removed without touching earlier successful archives. Keep the encryption identity available during server recovery; the archive alone cannot be decrypted without it.

## Verification

Local checks include lint, Astro checks/build with compiled navbar glass verification, locked extension builds and dependency audits. Focused regressions cover cross-instance Redis invalidation races, aggregate counts above 5,000, 201-record sitemap pagination, RSS failure/empty states and HTML cache admission/privacy. Browser checks cover carousel arrows/Home/End, 32px targets at 375px, hidden-panel semantics and offscreen video pause. Production rollout and recovery checks are recorded after deployment below.

No full load-capacity or WCAG certification is claimed. Media quality takes precedence over small file-size savings. Same-server backup placement and the decision not to introduce proposed product features are explicit user choices.
